# Form 10 Converter

A local desktop converter that imports a month-wise milk-procurement workbook and exports a FORM-10 `.xlsx` workbook.

## Workspace

- `crates/form10-core` — UI-independent domain models, source parsing, validation, preview calculations, and FORM-10 generation behind `ConverterService`.
- `crates/form10-ui` — Tauri 2 desktop application with a Svelte 5 and TypeScript frontend. The Rust host owns local workbook state and calls `form10-core`; the webview only receives display-safe summaries.

The workspace produces the `form10-converter` desktop executable.

## Supported files

- Input: `.xls` and `.xlsx`
- Output: `.xlsx`

All processing is local. No workbook data is sent over a network.

## Development

```bash
npm --prefix crates/form10-ui ci
npm --prefix crates/form10-ui run tauri dev
cargo fmt --all -- --check
cargo check --workspace --all-targets
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
npm --prefix crates/form10-ui run check
npm --prefix crates/form10-ui run build
npm --prefix crates/form10-ui run tauri build
```

The app uses native dialogs for workbook selection and export paths. Existing output files require an explicit confirmation before replacement.

## Windows distribution

Distribute the Windows installer generated by `npm --prefix crates/form10-ui run tauri build`, not a bare cross-compiled `.exe`. The installer includes the Microsoft WebView2 Runtime for offline installation. A GNU (`*-pc-windows-gnu`) executable also requires `WebView2Loader.dll` alongside the `.exe`; the Tauri NSIS/MSI bundle includes it automatically when it is present in the target output directory.

Browser Playwright tests use explicit mock mode. Native WebDriver tests use `tauri-driver` on Linux and Windows only; macOS does not expose a WKWebView driver for `tauri-driver`.

```bash
cargo install tauri-driver --locked
npm --prefix crates/form10-ui run test:e2e:tauri
```
